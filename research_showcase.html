Abstract

本项目探索将参考画风 A 与内容 B 分开输入 Anima，并通过单个 LoRA 调整画风迁移行为。已有实验表明，替换参考图会改变生成图像；但“参考产生响应”并不等于真实笔触已经迁移，也不证明内容与画风在内部表示中完全解耦。

现阶段我们同时展示有效响应和失败情况，结合受控条件、图像对照与特征空间统计检查模型行为。不同特征代理得到的结果可能不一致，需要以实际生成图和进一步的独立评估共同判断。

How does it work?

01 / FLOW MATCHING

生成目标：从噪声预测速度

把 C 编码成 latent，与随机噪声按 t 混合。模型接收带噪目标、B 和 A，拟合目标速度；训练时再由单步预测构造画风监督。

zC = E(C),   ε ∼ N(0, I)
zt = (1 − t) zC + t ε,   v* = ε − zC
ẑ0 = zt − t vθ,   Lflow = mean[(vθ − v*)²]

t 的采样：g ∼ N(0, 1)，u = sigmoid(g)，t = 3u / (1 + 2u)。ẑ0 是训练中的单步估计，不是最终多步生成图。

02 / STYLE STATISTICS

画风目标：多尺度相关性与边缘统计

对 latent 在 1、2、4 三个尺度做平均池化；Gram 比较前按通道中心化和标准化；均值与标准差在原池化 latent 上计算，另比较水平／垂直一阶差分统计。ρ 表示 Smooth L1 均值。

Gs(z) = F̃s(z) F̃s(z)T / Ns
Lstyle = Σs ws [ ρ(Gs(ẑ0), Gs(zC)) + 0.25 (ρ(μ̂s, μC,s) + ρ(σ̂s, σC,s)) ] + 0.10 Ledge
w = (1, 0.7, 0.4)

监督的直接比较对象是 ẑ0 与 C，不是输出与 A 的局部笔触逐块对齐。边缘项还包含差分特征 Gram，以及绝对均值、平方均值和标准差的比较。

03 / LOW-RANK UPDATE

一条 LoRA 与总损失

W′x = Wx + U(Dx),   ΔW = U D,   rank(ΔW) ≤ 32
L = λflow Lflow + λstyle Lstyle

9999 续训配置中 λflow = 1.25，λstyle 初始配置为 0.08；恢复控制器后首个记录值约 0.08087。0.15 是加权风格梯度范数／加权 flow 梯度范数的控制目标，不是固定画风 loss 权重。梯度只在部分审计步与选中样本上测量，实际比值不保证每步达到该目标。

样本怎样配对

一条训练记录由内容 B、配对目标 C 和参考 A 构成；A 与 C 使用同一个画风标签、不同内容组，且 A ≠ C。A 作为条件参与预测，流匹配和风格统计项的直接监督目标来自 C。相同标签不等于笔触完全一致，也不保证内容与风格独立。

清单按风格标签划分 train / validation / test：140 / 30 / 37；名称没有交集。像素级查重检查在这轮代码中处于关闭状态，近重复、视觉相似风格和底模预训练见过的图片均未排除。

一次更新如何运行

从 global step 9999 继续训练单个 rank-32 LoRA，底模冻结。1024 分辨率，等效 batch 16、microbatch 1，使用 7 个 checkpoint blocks；AdamW 参数为 β=(0.9, 0.999)、ε=10⁻⁸、weight decay=0。历史训练图像按 1024×1024 直接缩放，可能改变宽高比。

学习率由 1×10⁻⁵ 预热至 5×10⁻⁵；配置最多更新 1000 次，现有日志记录 789 次，结束于 10788。配置为每 100 次预览、每 200 次保存；这是配置，不代表每次执行都一定产物完整。

实际预览与训练限制

归档中有 9999 基线、10099 和 10499 等训练预览，固定计划包含训练锚点以及留出内容／标签案例。总览保留 B、C、A 和对应输出；标签或内容被计划留出，并不证明底模从未见过相似画风。

预览原图包含人物与训练参考，来源和公开权限还需逐图核对，未放进当前网页发布目录。下方训练曲线和示例图均来自已留存结果。

设备与运行时间

9999 续训预检记录 GPU 为 NVIDIA RTX 6000D，可见显存约 83.05 GiB；PyTorch 2.12.0+cu130、CUDA 13.0。配置的显存预算为 76 GiB，它不是实际已用显存。

789 条训练日志中，单次更新的记录耗时中位数约 36.20 秒；该计时覆盖样本准备和更新，不包括额外的预览及保存开销。单步 PyTorch 峰值已分配显存最高约 39.06 GiB，不等于整机占用。CPU 和操作系统型号尚未核实。

The research journey

我们实际训练过什么、得到什么、又排除了什么

早期阶段

6000 → 6280 → 7280 → 8280

历史记录包含多轮单 LoRA 强化和外部交叉预测。早期 checkpoint、输出和训练增量没有完整留存，不能将每一阶段的视觉变化归因于某一次改动。

主线续训

9999 → 10788：计划 1000，日志记录 789 次更新

分辨率 1024，等效 batch 16，rank 32；LoRA 学习率由 1×10⁻⁵ 预热至 5×10⁻⁵。主 loss 与画风 loss 分开记录；分段曲线不能代替生成图质量。

局部卷积

本地累计 300 + 云端 600 次更新

原 LoRA 冻结。云端记录 9600 次样本呈现、140 个风格标签；云端 0／400／600 步（累计 300／700／900 步）预览未建立稳定的外部笔触改善，部分案例有内容漂移。

动态增量

本地 30 + 云端 100 次更新

在 LoRA 10135 和已有卷积分支上继续训练，12 组 B／A 各比较增量 OFF／ON，一个种子。粉彩边缘、水墨纸感有局部响应；点彩、蓝晒仍不忠实。未建立动态增量的稳定额外收益。

两组小试

参考排序 / 配对纹理差：每组 control 与实验各 15 步

排序项仅在 3／15 步激活；配对纹理干预也只触发 3 次。少量预览未建立可靠改善，但不足以否定整个方法方向。

测量反例

优化代理分数，不等于图像更好

3 张图各做 60 次像素空间优化，StyleShot 相关距离下降约 80%–87%，视觉复核均未通过。该实验中 Anima 和 LoRA 更新次数为 0。

综合评测原计划 1232 条，本地档案记录 600 条；本页只报告实际留存的记录和明确标记的子集。

Inside the model

从生成图、参数和中间状态三个层面检查

参考图 A 有影响，但不等于笔触迁移成功

历史 2×2 单步干预中，固定 B、C、噪声和 t = 0.85，分别替换正确／错误参考。四组“错误 A 的 flow MSE − 正确 A 的 flow MSE”均为正：0.001882、0.006778、0.001610、0.005724。这个小实验支持条件响应存在，不能证明画风已迁移。

统计损失的一个具体盲区

把空间位置展平后，令 P 为置换矩阵。通道 Gram 对空间重排不敏感：

G(FP) = F̃ P PT F̃T / N = F̃ F̃T / N = G(F)

一个实际的方形 latent 转置实验中，相对 RMS 变化为 1.16，现有 style loss 却只有 5.96 × 10⁻¹⁴。这证明该测试中的统计量对这种结构变化不敏感；latent 转置不是现实图像旋转，flow loss 也不一定不变，不能将它当成泛化失败的唯一原因。查看原始汇总

One reference, multiple steps

在同一个 LoRA 内尝试目标分解与阶段拟合

我们用一张油画 A 作为参考、一张城市 B 作为内容，在同一个 LoRA 的一次采样轨迹内，比较原始生成、联合拟合与阶段拟合。颜色直方图、灰度 VGG 方向变化和局部特征距离作为三个参考代理；它们可能混入主体轮廓和亮度，不是已证实可以独立拼接的画风原子。

Lessons & next steps

从已经踩过的坑，明确下一轮如何避免重复

01　只盯 loss，容易优化到错误目标

已观察：像素优化可显著降低代理距离，但三例视觉复核失败。
下一步：同时固定种子看完整生成图和局部裁片，分别记录内容保持、笔触与颜色；把特征分数作为辅助。

02　参考条件存在，不代表传递了细节

已观察：换 A 会改变单步状态和输出，但某些结果主要改变颜色或粗线条。
下一步：固定 B 与种子切换 A，再固定 A 与种子切换 B；继续做同画风异内容、同内容异画风的匹配实验。

03　统计匹配可能忽略空间结构

已观察：多尺度 Gram 与统计项在特定转置反例上接近不变。
下一步：先验证局部特征能否区分画风与内容，再考虑把有效表征接入训练；这仍是待验证方案。

04　分支消融必须说清楚开关

已观察：动态增量 OFF 仍保留旧卷积和 LoRA；12 对输出的逐像素 RGB 绝对差的平均值为 0.572／255。
下一步：区分“无旧分支”和“仅关动态增量”，固定输入、种子与采样参数，不能把像素差解释为质量提升。

05　预处理会改变测试结论

已观察：历史综合生成把输入拉伸成方形；部分后续探针使用等比缩放与灰边。
下一步：训练与测试分别记录缩放、裁剪和填充；页面展示按原比例，比较时只在相同预处理下归因。

06　计划数、留出集与基准不能混写

已观察：1232 是原计划，已记录 600；138 是匹配子集；底模是否见过这些风格未知。
下一步：先封存按内容与画风独立划分的测试集，再做独立盲评和同协议外部方法比较。
